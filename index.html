06 · SHA-256

¿Qué significa 256 bits?

SHA-256 convierte datos de cualquier tamaño en una huella digital de tamaño fijo.

🔢

256 bits

El resultado tiene 256 bits, equivalentes a 32 bytes.

🔠

64 caracteres

Normalmente se representa con 64 caracteres hexadecimales. Cada carácter representa 4 bits.

🧩

Detectar cambios

Un cambio en los datos produce normalmente una huella muy diferente.

Ejemplo sencillo

El texto “Hola” y el texto “Hola!” generan hashes diferentes.

SHA-256("Hola") → hash A
SHA-256("Hola!") → hash B

¿Para qué se usa?

BancoChain utiliza hashes para identificar transacciones y bloques, y para comprobar si los datos coinciden con los valores calculados.

Recuerda: un hash no cifra ni permite recuperar el texto original. Ayuda a verificar integridad, pero no sustituye una firma digital.
07 · Glosario blockchain

Palabras importantes, explicadas fácil

Bloque

Contenedor de información que incluye datos de transacciones y valores para verificar su integridad.

Hash

Huella digital calculada a partir de datos.

previousHash

Hash del bloque anterior. Enlaza un bloque con el que le precede.

Merkle Tree

Árbol que combina hashes de transacciones hasta producir una huella final.

Merkle Root

Hash de la parte superior del árbol; resume las transacciones representadas en él.

Nonce

Valor que puede probarse o utilizarse una vez, según el mecanismo. Su función depende del contexto.

Mempool

Conjunto de transacciones pendientes de incluirse en un bloque o procesarse.

Nodo

Participante de la red que puede almacenar información o validar la cadena. Aquí los nodos son simulados.

Consenso

Mecanismo para comparar validaciones y decidir si se acepta una propuesta.

En una frase: el hash identifica los datos; previousHash enlaza bloques; Merkle Root resume transacciones; los nodos revisan la cadena.
08 · Criptografía

Hash, firma y cifrado son diferentes

SHA-256
🧬

Hash

Genera una huella digital para ayudar a detectar cambios. No demuestra por sí solo quién creó los datos.

Ed25519
✍️

Firma digital

La clave privada firma y la clave pública verifica. Ayuda a comprobar que la firma corresponde a los datos y a esa clave pública.

AES-GCM
🔒

Cifrado

Protege la confidencialidad. AES-GCM también permite comprobar la autenticidad de los datos cifrados.

PBKDF2

Derivación de claves

Usa una contraseña o secreto, una sal y un número de iteraciones para derivar una clave.

AES-256

Tamaño de clave

Indica una clave AES de 256 bits, equivalente a 32 bytes; no significa 256 caracteres.

REPLAY ATTACK

Repetición de solicitud

Ocurre cuando se intenta reutilizar un mensaje o solicitud anterior. Los identificadores y controles contra repeticiones pueden ayudar a prevenirlo.

Resumen: el hash ayuda a comprobar integridad; la firma verifica autenticidad e integridad; el cifrado protege la confidencialidad.

Contraseñas, tokens ni claves privadas. La auditoría debe ayudar a investigar sin exponer secretos.

Los nodos simulados no equivalen automáticamente a servidores independientes.

11 · Laboratorio y pruebas

Modificar una copia para aprender de los errores

El laboratorio permite experimentar con una copia aislada de la cadena para estudiar cómo se detectan los cambios.

🧪

1. Preparar

Crear una copia de la cadena para hacer pruebas.

2. Alterar

🔎

3. Validar

Comprobar hashes, Merkle Root y enlaces entre bloques.

♻️

4. Restaurar

Restablecer la copia para comenzar de nuevo.

¿Qué comprueban las pruebas?

El cálculo de hashes, enlaces entre bloques, árbol de Merkle, firmas Ed25519, nonce, intentos de repetición, consenso y comportamiento cuando un nodo está desconectado.

¿Qué significa que una prueba pase?

Que un comportamiento específico cumple el resultado esperado. No garantiza por sí solo que toda la aplicación esté libre de errores.
